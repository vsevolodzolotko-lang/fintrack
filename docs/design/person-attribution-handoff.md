# Handoff: атрибуція витрат по людині («хто витратив»)

Дизайн-задача: допрацювати лейаут трьох поверхонь під нову фічу. Технічна поведінка
і дані вже зафіксовані — тут усе, що потрібно
для дизайну. Базові токени, типографіка і загальний стиль — у `docs/design/README.md`
(та сама темна тема «Gold Money», Manrope + Space Grotesk, ті самі радіуси).

---

## Контекст фічі (1 абзац)

У пари спільний Monobank-рахунок з двома картками. Банківський API **не каже, чиєю
карткою** зроблена оплата, тому кожна витрата зі спільного рахунку приходить
«не розподіленою», і людина проставляється вручну. Ніякого автовизначення чи правил —
свідоме продуктове рішення. Особисті рахунки Партнера A атрибутуються автоматично.

## Дійові особи / кольори

| Персона | Ініціал | Колір (вже в токенах) |
|---|---|---|
| Партнер A (в БД `displayName: "Партнер A"`) | С (або В — див. відкрите питання №4) | `#5B8DEF` |
| Партнер B | І | `#E86BA5` |
| Не розподілено | ? | dim `#6c7185`, dashed border |

Дані, які фронт має для кожного елемента:
- `users: [{ id, displayName }]` — рівно двоє, порядок стабільний (Партнер A перший).
- На транзакції: `userId: string | null` (null = не розподілено).
- На дашборді: `byPerson: [{ userId | null, spent }]` — суми витрат за цикл по кожному
  + нерозподілене.

## Поверхня 1: Review (свайп-розбір, колесо категорій)

Поточний стан екрана: повноекранний оверлей `#0b0d12`; по колу — чипи категорій
(іконки), внизу «+» (нова категорія) і «Пізніше»; в центрі — картка транзакції
(radius 26, padding 22), яку тягнуть до категорії. Хедер: ✕, «Розгляд транзакцій»,
лічильник `{done}/{total}` золотом, прогрес-бар. Над колесом — банер-підказка,
який показує ціль драгу («Тягни картку до категорії» → назва категорії).

Що додається:

### 1a. Перемикач «Партнер A / Партнер B» на картці
- Зараз у шапці картки: кольорова аварка-кружечок з ініціалом + підпис
  (`Партнер A` / `Спільне`). **Замінюється** на два тапабельні чипи — `Партнер A` і `Партнер B`
  (радіус 999, як person-pill на дашборді).
- Стани: активний чип — колір персони (бордер + текст), неактивний — dim на прозорому.
- Дефолт: той, хто залогінений на цьому телефоні (тобто зазвичай власник телефону).
- Поведінка: тап по чипу лише перемикає особу, **не** гортає стос і не стартує драг
  (чипи перехоплюють pointer-події). Вибір категорії (докинув картку в чип категорії)
  зберігає категорію + людину разом.

### 1b. Гортання стосу тапом
- Тап по картці (down→up, зсув < 8px, поза чипами) = «подивлюсь пізніше в цій сесії»:
  картка з анімацією пірнає вниз (`translateY(26px) scale(.9)`, fade, ~220ms) і стає
  в **кінець** стосу; зверху з'являється наступна.
- Навіщо: Партнер B і Партнер A гортають чергу, кожен шукає і розбирає свої витрати.
- Лічильник `{done}/{total}` від гортання **не змінюється**.
- Якщо картка в стосі одна — тап нічого не робить.
- «Пізніше» (свайп вниз) лишається як було: прибирає картку з сесії зовсім.
- Дефолтний текст банера-підказки стає: `Тягни до категорії · тап — гортати стос`.
- Дизайн-питання: чи потрібен додатковий візуальний хінт про тап (наприклад,
  видимий краєчок наступної картки під верхньою)? Зараз стос виглядає як одна картка.

## Поверхня 2: Список «Витрати» (Transactions)

Поточний стан: вертикальний список карток (radius 18, padding 16): опис + мета-рядок
(дата · рахунок · ім'я) зліва, сума справа (Space Grotesk), під ними два селекти
(категорія / конверт).

Що додається:
- Ім'я з мета-рядка **прибирається**; замість нього — **круглий бейдж** біля суми
  (26px, ініціал, фон = колір персони на 18% прозорості, текст — світлий відтінок
  кольору персони). Як маленька аварка в застосунку моно.
- Нерозподілено: пустий бейдж `?`, dashed бордер, dim.
- Поведінка: тап по бейджу циклічно перемикає: `?` → Партнер A → Партнер B → Партнер A → … (миттєвий
  PATCH, без діалогів; повторний тап = виправлення). Бейдж є лише на витратах
  (не на доходах).
- Це також механізм розкидання старих витрат після релізу (бекфіл зробить їх `?`).

## Поверхня 3: Дашборд

### 3a. Пігулка-фільтр (хедер, справа)
- Було 2 сегменти (`Партнер A` / `Партнер B`), суто косметика. Стає **3 сегменти**:
  `Разом · Партнер A · Партнер B` (актив = золото на `rgba(245,166,35,.18)`, як зараз).
- Дефолт — «Разом». Вибір людини **реально фільтрує** всі цифри циклу:
  hero «можна витратити сьогодні», конверти, ліміти категорій, донат — рахуються
  лише по витратах цієї людини (бюджети лишаються спільними, від спільного доходу).
- Нерозподілені витрати видно лише в «Разом».
- Дизайн-питання: пігулка з трьох слів у рядку з kicker'ом може не влазити на 390px —
  можливо, компактніші лейбли або перенос.

### 3b. Блок «Хто скільки»
- Нова секція-картка за поточний цикл (пропонована позиція — після «Конвертів»,
  перед «Лімітами на життя»; можна пересунути).
- Рядки: ім'я + сума (Space Grotesk) + частка у % (`Партнер A — ₴6 400 · 62%`,
  `Партнер B — ₴3 900 · 38%`), відсортовано за сумою; якщо є нерозподілене — третій рядок
  `Не розподілено` dim-кольором.
- Дані завжди по повному циклу (не залежать від пігулки-фільтра).
- Дизайн-питання: чи хочемо тут візуалізацію (двоколірний горизонтальний бар з
  частками у кольорах персон #5B8DEF / #E86BA5) замість/на додачу до цифр.

## Обмеження

- Стилі — рукописний CSS з токенами в `:root` (без Tailwind); нові елементи мають
  використовувати існуючі токени й радіуси.
- Мобільний PWA, цільова ширина ~390px, нижній таб-бар 88px.
- Кольори персон — стабільні (Партнер A завжди синій, Партнер B завжди рожевий), у т.ч. в
  бейджах, чипах і барі часток.
- Іконки — lucide; чарти — Recharts.

## Відкриті дизайн-питання (зібрано з тексту)

1. Хінт про «тап — гортати стос» на картці Review (краєчок наступної картки? текст?).
2. Розміщення чипів Партнер A/Партнер B на картці Review: шапка картки чи під сумою.
3. Пігулка з 3 сегментів у хедері дашборда на 390px.
4. Ініціал Партнера A: в БД він «Партнер A» → бейдж «В». Лишаємо «В» чи показуємо «С»
   (тоді треба перейменувати displayName у БД — дешево, або мапити на фронті — не хочеться).
5. Блок «Хто скільки»: чи додаємо двоколірний бар часток.
